# Помощник закупщика

Локальный MVP для кейса HackAlem компании «Электрокомплект».
Репозиторий команды: `hack-3b47610b-blank`.

Выполнены этапы 1–11: локальное приложение и импорт шести книг каждого поставщика,
Systeme Electric и IEK, включая скрытые данные, версии и происхождение значений.
Можно загрузить отчёты, выбрать сохранённый снимок и проверить исходную ячейку.
Для IEK извлекается встроенный архивный прайс; перевод единиц требует явного
подтверждения. Работают сверка альтернативных источников, версионирование
бизнес-параметров и проверка готовности каждого SKU. Работает версионированный
месячный прогноз регулярного спроса со сравнением простых моделей и baseline.
Расчёт пополнения доступен через CLI и русскоязычный интерфейс, принимает
сохранённый прогноз этапа 8 и хранит неизменяемые сценарии. Проекты заказов
поддерживают правки менеджера, локальное утверждение и проверяемый CSV/XLSX;
отправки поставщику нет. Отдельный синтетический набор с фиксированным
seed покрывает 17 сценариев и содержит эталоны для проверки будущих этапов.
Регулярный спрос готовится отдельной версией: возвраты сохраняют знак, а
разовые крупные покупки получают объяснимый статус и требуют заданного правила
или решения ответственного сотрудника.
Подтверждённые полнодневные отсутствия товара дают отдельную оценку
исторически упущенного спроса. Для реальных файлов без дневного журнала
точная коррекция недоступна; ручные интервалы доступны только как сценарий.

## Запуск в Windows PowerShell

Проверенное окружение: Python 3.14.7 и uv. Версии зависимостей закреплены в
`uv.lock`; SQLite входит в стандартную библиотеку Python.

```powershell
Set-Location 'C:\Users\bozta\Desktop\hackalem\hack-3b47610b-blank'
uv sync --locked
uv run --locked python -m streamlit run app.py
```

Откройте <http://127.0.0.1:8501>. Остановить сервер в его терминале: `Ctrl+C`.
Выберите поставщика и нажмите «Импортировать …» или выберите сохранённый снимок.
При повторной загрузке неизменённых файлов данные не удваиваются.
Активация виртуального окружения и изменение ExecutionPolicy не нужны.
При первой установке требуется доступ к источникам зависимостей; после установки
приложение работает локально и не требует платных API.

Окружение уже установлено на текущем компьютере. Можно запустить напрямую:

```powershell
Set-Location 'C:\Users\bozta\Desktop\hackalem\hack-3b47610b-blank'
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Если порт 8501 занят, добавьте `--server.port 8502` и откройте соответствующий адрес.
Сервер слушает только `127.0.0.1`, сбор статистики Streamlit отключён.

## Пути и исходные файлы

По умолчанию исходные отчёты находятся в корне проекта, в папках `IEK` и
`Systeme electric`. Импорт читает выбранного поставщика, не изменяя PDF/XLSX.
Рабочая база создаётся отдельно: `.local/hackalem.sqlite3`. Прежние схемы
автоматически мигрируют в схему 9 с сохранением метаданных и снимков.

Пути можно переопределить переменными окружения перед запуском:

```powershell
$env:HACKALEM_SOURCE_DIR = 'C:\Users\bozta\Desktop\hackalem\hack-3b47610b-blank'
$env:HACKALEM_DATA_DIR = '.local'
uv run --locked python -m streamlit run app.py
```

Относительные пути разрешаются от корня проекта, независимо от текущей папки
терминала. Отсутствующий каталог источников даёт предупреждение; папки источников
не создаются автоматически. Размещать хранилище внутри папок поставщиков нельзя.
При ошибке пути или несовместимой версии базы приложение показывает причину.
Переменные окружения действуют для текущего процесса/терминала; файл `.env`
автоматически не загружается.

Исходные документы, локальная база, окружение и генерируемые файлы исключены из
Git через `.gitignore`. Исключение из Git не удаляет файлы с диска.

## Импорт и проверка без браузера

```powershell
uv run --locked python -m hackalem import-systeme
uv run --locked python -m hackalem import-iek
uv run --locked python -m hackalem list-snapshots
uv run --locked python -m hackalem report --snapshot 1
uv run --locked python -m hackalem trace --snapshot 1 --source current --sheet TDSheet --cell AP3
```

В командах `report` и `trace` замените `1` номером нужного снимка из списка.
Команды возвращают JSON; ошибка даёт код завершения 1. Первая загрузка читает
весь выбранный набор и может занять около минуты; повторная использует сохранённые версии.

Каждый снимок относится к одному поставщику и фиксирует ровно одну версию каждого типа источника, хэши кода
и зависимостей, правила преобразования и параметры. Изменение файла создаёт
новую версию, предыдущие остаются доступны. Имя участвует в версии, поскольку
в нём может находиться дата среза. Перемещение того же файла сохраняет версию
и добавляет путь в журнал расположений. Приложение не складывает разные
снимки или альтернативные отчёты о продажах.

В папке импорта должен находиться один XLSX каждого из шести типов. При
неизвестной структуре, неоднозначном составе или повреждённой книге вся новая
загрузка отменяется, старые снимки сохраняются. Ошибочные ячейки регистрируются
отдельно и не мешают сохранять корректные строки. Исходные формулы не пересчитываются;
загружаются выражения и результаты, сохранённые в Excel.

В исходном наборе Systeme есть 26 нулевых кратностей месячного отчёта, пустые количества,
отрицательные операции, неоднозначные категории, ETA без года и ошибка AP/AQ
«13 месяцев / 12». Они сохраняются с замечаниями. Кратность не объявляется MOQ,
«СС реал» — закупочной ценой, а BB «Заказ» — подтверждённым поступлением.
Замечания видны в отчёте согласования; прогноз относится к следующим этапам.

## Особенности IEK

Загружаются 171 603 документные строки, месячные продажи 2 463 SKU, начальные
остатки 2 853 SKU и 306 строк поступлений для 300 SKU. Шесть колонок пути
разворачиваются с номером заказа, датой и обещанным сроком «поступление до».
Это не фактическая приёмка. Пустые коды и служебные 0/1 не становятся товарами.

MOQ содержит 1 938 строк, включая повторный код, и 15 ошибок `#N/A`.
Ошибки сохраняются с SKU и координатами, без замены минимумом 1. Встроенный
прайс от 03.08.2026 содержит 39 275 артикулов. Кэш читается из XLSX без открытия
внешней ссылки. Его базовые цены, статусы, единицы, кратность и минимум остаются
архивными наблюдениями, а не подтверждёнными действующими условиями.

Для проверки конкретного товара используйте команду (номер снимка взять из списка):

```powershell
uv run --locked python -m hackalem units --snapshot 2 --sku 280200087_
uv run --locked python -m hackalem trace --snapshot 2 --source incoming --sheet Лист4 --cell F471
```

В интерфейсе IEK введите код товара в блоке единиц. Коэффициент из названия —
только предложение. Для перевода укажите проверенный коэффициент, автора,
основание и отметьте подтверждение. Для 280200087_ предлагается 4: после
подтверждения 5 комплектов дают 20 штук. Решение сохраняется отдельно и действует
только для выбранного SKU и снимка. Оно не подтверждает архивные цены и MOQ.
Без подтверждения перевод не выполняется; неизвестные единицы блокируют его.

Общий интерфейс чтения и импорта — `hackalem/services/imports.py`. Структуры
описаны в `docs/IMPORT_SYSTEME.md` и `docs/IMPORT_IEK.md`.

## Согласование источников и готовность данных

Выберите снимок и нажмите «Проверить данные». Отчёт сохраняет весь ассортимент,
сверяет продажи по SKU и месяцу, отдельно показывает разный охват источников,
пустоты, ошибки и количественные расхождения. AP/AQ «13 месяцев / 12» остаётся
замечанием. Альтернативные продажи не складываются.

Без бизнес-параметров товары получают «Не хватает данных». В блоке «Задать
параметры и источник продаж» можно сохранить JSON с автором, основанием и
статусом каждого значения: `confirmed` или `scenario`. Правила и формат
описаны в [docs/DATA_CONTRACT.md](docs/DATA_CONTRACT.md). Настройка и результат
проверки привязаны к снимку; предыдущие версии остаются доступны. Для просмотра
выбранной истории, её происхождения и допущений выберите товар в отчёте.

```powershell
uv run --locked python -m hackalem quality --snapshot 1
uv run --locked python -m hackalem quality-report --run 1 --sku 300200428_
uv run --locked python -m hackalem configure --snapshot 1 --file .local/parameters.json
uv run --locked python -m hackalem configs --snapshot 1
uv run --locked python -m hackalem quality --snapshot 1 --config 1
```

Замените номера фактическими ID из ответа команд. Файл `parameters.json`
нужно подготовить по контракту; автоматически заполненных бизнес-значений нет.
«Достаточно данных» означает готовность входов, а не готовый или утверждённый
заказ. Сценарий допускается только явным вызовом сценарного режима сервиса;
товар с недостающими данными не проходит входной контроль расчёта.

## Синтетический проверочный набор

Набор хранится отдельно от реальной базы. Команда создаёт 17 вымышленных товаров
двух поставщиков и историю за январь 2024 — декабрь 2025, затем запускает общую
сверку и проверку готовности. Все настройки явно сценарные.

```powershell
uv run --locked python -m hackalem synthetic-generate --seed 20260923
uv run --locked python -m hackalem synthetic-report --dataset .local/synthetic/synthetic-1-seed-20260923
```

Повтор с тем же seed переиспользует целый набор. Изменение seed создаёт отдельный
dataset; чужая папка и повреждённый набор не перезаписываются. Для другой
выходной папки задайте `--output-root`.

Чтобы открыть набор в обычном интерфейсе:

```powershell
$env:HACKALEM_DATA_DIR = '.local/synthetic/synthetic-1-seed-20260923/model'
uv run --locked python -m streamlit run app.py
```

На экране появится предупреждение «СИНТЕТИЧЕСКИЙ ПРОВЕРОЧНЫЙ НАБОР», импорт
реальных Excel в эту базу заблокирован. Выберите снимок и сохранённую проверку.
После остановки приложения для возврата к реальной базе задайте
`$env:HACKALEM_DATA_DIR = '.local'` (либо свой прежний путь).

`model/` содержит наблюдаемые данные и общую нормализованную SQLite-базу.
В отдельной `validation/` лежат скрытый спрос, эталонные метки и критерии;
они не входят во входы модели. Версии, 10 ручных расчётных примеров и заранее
зафиксированные допуски описаны в [docs/SYNTHETIC_DATA.md](docs/SYNTHETIC_DATA.md).
Очистка регулярного спроса проверяется на этом наборе отдельно от исходных
операций. Качество прогноза проверяется отдельным evaluator этапа 8; синтетическая
истина не передаётся модели. Восстановление stockout и качество заказа ещё не
проверены. Этот набор не доказывает точность на реальном бизнесе.

## Подготовка регулярного спроса

Выберите снимок в приложении, затем в блоке «Регулярный спрос» укажите дату
среза и правило. Правило по умолчанию оставляет спорные крупные документы на
проверке. Сохранённая версия показывает подписанное исходное количество,
регулярную часть, возвраты, исключённую часть и проектное обязательство по
месяцам. Исходные Excel и транзакции при этом не меняются.

В командной строке:

```powershell
uv run --locked python -m hackalem clean --snapshot 2 --as-of 2026-09-22
uv run --locked python -m hackalem cleaning-runs --snapshot 2
uv run --locked python -m hackalem cleaning-report --run 1 --sku 130200305_
```

Для проверки автоматического исключения уверенных одиночных случаев передайте
`--policy exclude_high_confidence`; без обезличенного ID клиента такие случаи
всё равно останутся кандидатами. Ручные решения передаются JSON-массивом через
`--decisions ПУТЬ`; точный контракт — в
[docs/DATA_CONTRACT.md](docs/DATA_CONTRACT.md). Реальная строка IEK на 210 000
отмечается кандидатом, но не признана ошибкой.

## Прогноз регулярного спроса

После сохранения совместимых проверки качества и подготовки спроса укажите SKU
и JSON-настройку в блоке «Прогноз регулярного спроса». Модель сравнивает
сезонный аналог, ограниченный затухающий тренд и Croston SBA на последовательных
временных разбиениях. Отчёт показывает WAPE, MAE в единицах товара, bias,
baseline и ограничения.

```powershell
uv run --locked python -m hackalem forecast --quality-run 2 --cleaning-run 1 --sku 130200305_ --config .local/forecast.json
uv run --locked python -m hackalem forecast-runs --snapshot 2 --sku 130200305_
uv run --locked python -m hackalem forecast-report --run 1
```

Для синтетического входа добавьте `--allow-scenario`. Точный формат настройки,
режимы бизнес-прироста, fallback новинки и границы этапа описаны в
[docs/FORECASTING.md](docs/FORECASTING.md). При наличии совместимой оценки
этапа 7 передайте её через `--lost-demand-run`; иначе ограничение явно
сохраняется в отчёте.

## Упущенный спрос

Выберите версию регулярного спроса и SKU в блоке «Упущенный спрос при отсутствии
товара». Синтетический набор содержит полнодневное наблюдение наличия;
реальные исходные книги его не содержат. Поэтому для реальных SKU интерфейс
показывает «точная коррекция недоступна», а не нулевую потерю.

```powershell
uv run --locked python -m hackalem lost-demand --cleaning-run 1 --sku 130200305_
uv run --locked python -m hackalem lost-demand-runs --cleaning-run 1
uv run --locked python -m hackalem lost-demand-report --run 1
```

Номера версий берите из фактического вывода. Для проверки сценария с
вручную заданными интервалами используйте `--scenario-evidence ПУТЬ.json`.
Правила длительности, сравнения дней, ограничения экстраполяции и пример
JSON описаны в [docs/LOST_DEMAND.md](docs/LOST_DEMAND.md). Историческая
добавка входит только в обучающую историю будущего прогноза; новый заказ она
сама по себе не увеличивает.

## Сценарный расчёт пополнения

Для расчёта без интерфейса подготовьте JSON с идентификаторами версий качества
и регулярного спроса, явной датой среза и версионированным прогнозом. Для
реальных исходных файлов исходный срез — `2026-09-22`; дата компьютера не
подставляется. Формат и ограничения: [docs/REPLENISHMENT.md](docs/REPLENISHMENT.md).

```powershell
uv run --locked python -m hackalem replenish --file .\my_replenishment.json
uv run --locked python -m hackalem replenishment-report --run 1 --sku ВАШ-SKU
```

Основной путь использует `forecast_run_id` этапа 8. Ручной прогноз остаётся
явным сценарным fallback. Номер `run_id` возьмите из вывода первой команды.

## Интерфейс закупщика

В боковой панели выберите dataset, поставщика, охват и деловую дату, затем
версию данных. Раздел «Данные и проверки» содержит импорт и подготовительные
версии этапов 1–8. В «Рекомендациях» выберите совместимые версии качества,
очистки и прогнозов и нажмите «Рассчитать рекомендации». Результат сохраняется
под `run_id`; поиск, фильтры и сортировка не пересчитывают его.

«Карточка товара» показывает исходный и очищенный спрос, аномалии, наличие,
прогноз, будущий остаток и компоненты формулы. В «Сценариях» можно задать
изменение спроса и задержку поступлений с автором и основанием. Такой запуск
создаёт новый `run_id`, сохраняя базовый расчёт. Синтетические и сценарные
результаты маркируются. Количества разных единиц не объединяются; стоимость
не выводится без подтверждённых цены и валюты. В разделе «Заказы» рекомендация
становится версионированным проектом: выбранное количество хранится отдельно,
а утверждённая версия остаётся неизменной. Черновые, сценарные и синтетические
файлы получают явную маркировку. Подробности: [docs/ORDERS.md](docs/ORDERS.md).

## Проверка

```powershell
uv run --locked python -m pytest -q
```

Проверяются миграция без потери метаданных, отказ от изменения чужой базы,
парсинг Excel, идемпотентность, смена версий, откат ошибочной загрузки и экран
импорта/происхождения через Streamlit AppTest. При наличии исходных отчётов
дополнительно выполняется приёмка реальных книг обоих поставщиков; без них
соответствующие тесты пропускаются. Для внешней папки приёмки задайте `HACKALEM_REAL_SOURCE_DIR`.
Также проверяются сверка источников, выбор истории, сценарные ограничения,
параметры, обработка возвратов/разовых документов, временная проверка прогнозов,
сезонность, рост, fallback новинок, причинная оценка упущенного спроса,
расчёт пополнения и сохранение результатов.
Проверки изменения файлов работают только
с временными копиями.

Критические правила дальнейшей разработки: реальные и синтетические данные
разделяются, неизвестные бизнес-параметры не придумываются, ошибки отдельных
товаров не теряют остальные строки, утверждение заказа выполняет человек.
Отправки поставщикам в локальном MVP нет. Прогноз не является проектом заказа
или его утверждением.
