# Технический контракт импорта Systeme Electric — этап 2

Документ описывает извлечение и хранение данных. Согласование противоречащих источников, выбор бизнес-правил, прогноз и заказ относятся к следующим этапам. Результаты выполненных проверок фиксируются отдельно в `docs/STATUS.md`.

## Вход и границы

`import_systeme(Settings)` читает XLSX из `HACKALEM_SOURCE_DIR/Systeme electric`; временные файлы Excel с префиксом `~$` пропускаются. Нужен ровно один файл каждого из шести типов:

| `source_kind` | Содержание |
|---|---|
| `multiples` | Справочник товаров, артикулы и кратность |
| `transactions` | Строки документов с датой, складом и количеством |
| `monthly_stock` | Месячная история остатков |
| `monthly_sales` | Месячные продажи и исходная кратность |
| `seasonality` | Исходные агрегаты сезонности |
| `current` | Рабочая таблица с продажами, остатками, резервами, категориями, исходными коэффициентами и путём |

Тип определяется по заголовкам в первых 12 строках, а не имени файла. Все листы читаются, включая скрытые; нераспознанный дополнительный лист сохраняется в исходных строках с предупреждением. Неизвестный или неоднозначный основной шаблон, недостающий тип либо два файла одного типа отклоняют весь новый импорт без частичного набора.

Импорт читает зафиксированные bytes файлов и разбирает временные копии в рабочем каталоге. Исходные XLSX не изменяются, внешние ссылки не обновляются, формулы не пересчитываются. Ошибочная отдельная ячейка сохраняется как проблема; независимые корректные строки продолжают обрабатываться.

## Структуры данных

`parse_workbook(Path) -> ParsedWorkbook` возвращает `source_kind`, `snapshot_date` и списки словарей. В SQLite к каждой записи добавляется `file_id`.

| Список / таблица SQLite | Основные поля |
|---|---|
| `sheets` / `import_sheets` | `sheet`, `state`, `declared_dimension`, фактические `max_row`, `max_column` |
| `raw_rows` / `source_rows` | `sheet`, `row`, `cells`; в SQLite последнее хранится как `cells_json` |
| `products` | `sheet`, `row`, `sku`, `name`, `article`, `unit`, `cell` |
| `transactions` | `sku`, `occurred_at`, `document_number`, `document_type`, `unit`, `warehouse`, `quantity`, `state`, происхождение |
| `monthly_values` | `sku`, `period`, `series` (`sales` или `stock`), `quantity`, `state`, происхождение |
| `measures` | `sku`, `metric`, `number`, `text`, `state`, происхождение |
| `seasonal_values` | `period`, `value`, `state`, происхождение; без SKU |
| `issues` / `import_issues` | `severity` (`warning` или `error`), `code`, `message`, `sheet`, необязательные `row`, `cell` |

`period` имеет вид `YYYY-MM-01`; даты документов сохраняются в ISO-формате. Коды и номера документов сохраняются строками. Числовой исходный код получает предупреждение: утраченные Excel ведущие нули не восстанавливаются предположением.

Ключ транзакции включает файл, лист и физическую строку. Одинаковые продажи в разных строках не удаляются. `products` содержит первое вхождение SKU на листе; повторения справочника отмечаются, а фактические строки и их происхождение остаются сохранены.

## Значения и происхождение

| `state` | Значение |
|---|---|
| `value` | Распознанное значение, включая явный ноль и отрицательное количество |
| `blank` | Пустая ячейка/пустое значение; числовое поле остаётся `None` / SQL `NULL` |
| `error` | Ошибка Excel, отсутствующий кэш формулы или неподходящее значение числового поля; нормализованное число `None` / `NULL` |

Отрицательное количество не меняет знак и не удаляется; добавляется `NEGATIVE_QUANTITY`. Пустота не превращается в ноль. Отсутствующий кэш формулы даёт `FORMULA_CACHE_MISSING`, а не результат самостоятельного вычисления.

В `cells` ключом служит буква столбца, например `H`. Ячейка содержит `value` (сохранённый результат), `formula` (исходная формула или `None`), `data_type`, `number_format`; при сохранённой ошибке может присутствовать `cached_error`. Полностью пустые строки и ячейки могут отсутствовать в разреженном представлении. Это извлечённые данные, а не полный архив XLSX со всем оформлением.

Объявленный размер XML хранится для проверки, но не ограничивает чтение строк. `trace_cell(database_path, snapshot_id, source_kind, sheet, cell)` возвращает файл, исходную ячейку, связанные нормализованные записи и относящиеся к ней проблемы. Одна ячейка может иметь несколько нормализованных применений: например, заголовок ETA используется несколькими SKU. В ответе нужно учитывать поле `table`, а не выбирать первую запись вслепую.

## Имена показателей `measures`

| Метрики | Смысл исходного поля |
|---|---|
| `order_multiple` | Кратность; самостоятельный MOQ не назначается |
| `reported_total_sales` | Исходный итог месячных продаж |
| `reported_last12_total`, `reported_last12_average` | Сохранённые показатели «последних 12 месяцев»; не исправленный прогноз |
| `reported_annual_sales`, `reported_annual_average` | Годовые показатели; год определяется исходным заголовком через происхождение |
| `reported_growth_rate`, `reported_seasonal_change` | Исходные исторические коэффициенты, не бизнес-план прироста |
| `stock`, `reserved_stock`, `free_stock` | Остаток, резерв и свободный остаток, сохранённые раздельно |
| `display_stock`, `sales_floor_stock`, `distribution_center_stock`, `retail_stock` | Отдельные складские поля без предположения об их взаимной независимости |
| `proposed_order`, `incoming_quantity`, `incoming_eta_label` | Проект заказа, количество в пути и исходный текст даты поступления |
| `category`, `reported_cost`, `reported_stock_cover`, `weight` | Исходная категория, «СС реал», покрытие и вес; неподтверждённый бизнес-смысл не назначается |

Исходные коэффициенты и прочие формулы сезонных листов сохраняются в `raw_rows`. `seasonal_values` содержит только наблюдения верхнего блока «год × месяц», включая пустые месяцы; это отдельный источник с неустановленной единицей, а не спрос конкретного товара.

## Версии и выбор источников

Этап 2 создал схему SQLite версии 2; этап 3 добавляет схему 3 для IEK с сохранением этих таблиц и снимков. Общий API доступен через `hackalem.services.imports`; снимки Systeme остаются связаны с поставщиком Systeme Electric. `import_files` хранит хэш bytes, имя, первоначальный путь, время импорта UTC, дату среза и версии правил/парсера. Другие обнаруженные пути записываются в `import_locations`.

Идентичность импорта: `(sha256, source_name, rules_version, parser_version)`. Повтор той же комбинации переиспользует данные; изменение содержимого, имени или правил создаёт новую версию. Имя включено потому, что полная дата среза `current` извлекается из имени файла. Это заявленная дата источника; для других типов она не назначается автоматически. Частичный заголовок ETA «24.09» не получает год из имени файла.

`snapshot` — выбранный набор входных версий, а не физический остаток на одну общую дату. Он содержит ровно по одному `file_id` каждого типа. Сохраняются хэши кода `hackalem/**/*.py`, `pyproject.toml`, `uv.lock`, JSON параметров и его хэш. Совпадение состава, кода и параметров переиспользует снимок. Старые наборы не редактируются и не складываются с новыми.

На этапе 2 параметры обработки фиксированы:

```json
{"dataset":"real","blank_policy":"preserve","eta_year":null,"sales_authority":null,"calculation_version":"not-implemented-stage-2"}
```

Изменять эти значения пока нельзя. API допускает дополнительные именованные JSON-метаданные, но они не меняют расчёт или трактовку пустот/ETA. CLI отдельного ввода параметров не имеет. `create_snapshot(...)` позволяет выбрать точное соответствие шести типов ранее сохранённым версиям; `read_records(...)` требует `snapshot_id`, `source_kind` и таблицу явно. Альтернативные источники продаж автоматически не объединяются.

## Команды CLI

Выполнять из корня проекта с установленными зависимостями. Пути задаются `HACKALEM_SOURCE_DIR` и `HACKALEM_DATA_DIR`; относительные пути разрешаются от корня проекта. Число `1` ниже заменить нужным `id` из списка снимков.

```powershell
uv run --locked python -m hackalem import-systeme
uv run --locked python -m hackalem list-snapshots
uv run --locked python -m hackalem report --snapshot 1
uv run --locked python -m hackalem trace --snapshot 1 --source current --sheet TDSheet --cell AP3
```

Успешные команды выводят JSON в UTF-8. Ошибка даёт сообщение в stderr и код завершения 1. Отчёт содержит количества записей, перечень листов, версии, полные счётчики проблем и не более 100 примеров проблем; этот лимит не удаляет остальные записи из базы.

## Что импорт не утверждает

Нет client_id, подтверждённого журнала stockout, согласованного источника продаж и срока новой поставки. Кратность не равна самостоятельному MOQ; категории и «СС реал» не расшифрованы; свободный остаток уже учитывает резерв. Ошибка исходного окна AP/AQ отмечается, а формула не исправляется. Данные не служат готовым прогнозом или разрешением на закупку. Импорт IEK, синтетический набор, согласование источников и бизнес-расчёты в этап 2 не входят.
