# Итоговая приёмка кейса HackAlem

Дата проверки: 23.09.2026. Требования сверены с исходным PDF, разделами
«Must have», «Ограничения» и «Артефакты». Это приёмка локального MVP:
реальные источники подтверждают импорт и ограничения данных, синтетический
эталон — проверяемое поведение алгоритма. Экономия, уровень обслуживания и
точность на реальном спросе не заявлены.

## Пять обязательных требований

| Требование | Проверка и фактический результат |
|---|---|
| Влияние всех входов | `test_case_acceptance.py` проводит независимые изменённые источники через quality → cleaning → forecast → replenishment. База: потребность 170, заказ 180; продажи/прирост: 242/252; увеличение остатка/пути: 146/156; политика категории: 110/120. Проверены значения до округления и итог. |
| Сезонность и устойчивый рост | Стабильный, сезонный и растущий SKU проходят заранее заданные пороги этапа 5; пик сезонного прогноза совпадает с июлем, прогноз роста сохраняет направление. Метрики ниже. |
| Компенсация подтверждённого отсутствия | На `SYN-A-009` исторический прогноз августа меняется с 119 до 217 при скрытом спросе 217; WAPE к истинному регулярному спросу падает с 4,11% до 0,27%. Улучшается именно прогноз, не только восстановленная история. |
| Разовая сделка не раздувает регулярный заказ | Парные истории с добавленной сделкой 500 и без неё дают одну потребность 17,354839 и заказ 18. Все 24 повторные покупки по 80 сохранены; суммарный повторный спрос 4835/4835 и растущий 12757/12757. |
| Объяснимые заказы по поставщикам | `test_demo.py`, `test_orders.py` и полный AppTest: два проекта поставщиков, формула и источники каждой строки, ручная правка, review → approved, новая версия после утверждения. CSV/XLSX повторно читаются и сверяются с утверждённым снимком; все 8 demo-выгрузок имеют `SYNTHETIC_SCENARIO`. |

Допуски `hackalem/synthetic/validation_spec.json` не изменялись. Проверки
не объявляют синтетический сценарий реальным подтверждённым заказом.

## Историческая проверка

Фиксированный seed `20260923`, наблюдения 2024–2025, синтетический срез
01.01.2026. Скрытый истинный спрос читает только evaluator после работы модели.
Временные точки backtest относятся к 2025 году; подготовка и модель
переобучаются на прошлом каждой точки. Это не случайное перемешивание месяцев.

| Сценарий | WAPE к истинному спросу | MAE, шт. | Средняя ошибка, шт. |
|---|---:|---:|---:|
| Стабильный спрос `SYN-A-001` | 1,90% | 5,75 | +3,92 |
| Сезонный спрос `SYN-A-002` | 1,41% | 4,92 | −0,92 |
| Устойчивый рост `SYN-A-003` | 3,20% | 22,90 | −8,64 |
| Stockout, исходные продажи | 4,11% | — | — |
| Stockout, подтверждённая коррекция | 0,27% | — | — |

Для stockout в августе абсолютная ошибка 98 → 0. Модель не получает скрытый
спрос при обучении. WAPE/MAE/bias, точки backtest и сравнение с baseline
сохраняются в JSON прогнозов; evaluator сравнивает их с независимой истиной.
Наличие более низкой ошибки на этих сценариях не доказывает преимущество
каждой модели над лучшим baseline и не доказывает причинную экономию.
Стабильная и сезонная модели совпали с baseline «тот же месяц прошлого года»
(разница WAPE 0). На растущем SKU тренд дал WAPE 3,20% против 4,96% у лучшего
baseline «последний завершённый месяц», выигрыш 1,75 процентного пункта.

На реальных отчётах историческая точность прогнозов не измерена: нет
подтверждённых бизнес-входов, дневного наличия и эталона спроса. Ни одна
реальная строка в проверенном исходном наборе не допущена к подтверждённому
заказу. Отчёт подготовки продаж не называется прогнозом или заказом.

## Границы и регрессии

| Проверка | Где подтверждена |
|---|---|
| Повторный импорт без удвоения; изменённая версия сохраняет прошлую | `test_systeme_real.py`, `test_iek_real.py`, импортные тесты; изменения только временных копий XLSX |
| Пустое значение отдельно от нуля, отсутствующее ограничение | quality/import tests, `test_replenishment.py`, synthetic SKU неизвестного значения |
| `300+60−90−100=170`, кратность12 →180; ноль не вызывает MOQ | `test_replenishment.py`, сквозная приёмка входов |
| 5 комплектов ×4 =20 штук; MOQ и кратность применяются после перевода | `test_replenishment.py` |
| Резерв не вычитается дважды, проект отделён от регулярного спроса | `test_replenishment.py`, `test_case_acceptance.py` |
| Частичный месяц исключён; месячный остаток не даёт точных дней отсутствия | cleaning/forecasting/lost_demand tests |
| Отсутствие актуального IEK-остатка блокирует реальный результат | `test_iek_real.py`, quality tests и замер реального набора |
| Поздний приход изменяет ранний риск и не считается прибывшим | `test_demo.py`, `test_replenishment.py` |
| Дата/quality/snapshot/supplier/dataset сбрасывают старые активные ссылки | 5 новых AppTest-регрессий; два разных dataset с одинаковыми run_id не смешиваются |
| Утверждение не захватывает устаревшие количества при конкурентной правке | `test_orders.py`: транзакционная повторная проверка всей версии |
| Текст метаданных не превращается в формулу; длинный JSON не обрезается | `test_orders.py`: все XLSX-листы, снимки больше 32 767 символов, CSV с пробельным префиксом |
| Backup включает WAL; восстановление не перезаписывает данные | `test_backup.py`: Online Backup API, integrity/FK checks, отказ для чужой/отсутствующей базы |
| Повтор прогноза не переобучает модель и сохраняет шлюзы проверки | `test_forecasting.py`: раннее чтение версии, новый config создаёт новый run, запрет сценария сохраняется |

Дата риска приблизительна при равномерном дневном распределении месячного
прогноза. Локальная запись ответственного не является проверкой личности.
Выгрузка ещё требует пробного импорта в конкретную 1С; автоматическая отправка
и облачное развёртывание отсутствуют.

## Воспроизведение

В корне проекта, Windows PowerShell:

```powershell
uv sync --locked
uv run --locked python -m pytest -q
uv run --locked python -m hackalem demo --output-root .local/demo
uv run --locked python -m scripts.benchmark_demo --output-dir .local/demo-benchmark-new
uv run --locked python -m scripts.benchmark_real --output-dir .local/real-benchmark-new
```

Для benchmark нужны новые папки; повторные measurements не перезаписывают
старые доказательства. Для реального замера нужны локальные папки `IEK` и
`Systeme electric` с 12 XLSX; при другом расположении добавьте
`--source-dir 'C:\путь\к\исходникам'`. Срез явно задан 22.09.2026.
Скрипты сохраняют `benchmark.json`, отдельные профили и проверки одинаковых
идентификаторов. Реальный отчёт также содержит SHA-256 исходников до/после;
его нельзя публиковать как открытый артефакт. Синтетический отчёт
`acceptance-history.json` отделяет evaluator от расчётного пути.
