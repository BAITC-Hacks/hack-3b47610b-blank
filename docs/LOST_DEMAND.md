# Оценка упущенного спроса: этап 7

Оценка дополняет **историческую обучающую** продажу, но не создаёт
задолженность к текущему заказу. Она хранится отдельной неизменяемой версией
поверх выбранной подготовки регулярного спроса. Исходные Excel, транзакции и
версии этапа 6 не меняются. Снимок, SKU, дата среза, версия кода и правил
`lost-demand-1` входят в fingerprint результата.

## Доказательство отсутствия

Источник должен описывать состояние товара в том же охвате складов в течение
**полных 24 часов каждого дня**. Синтетический набор содержит такой журнал
`synthetic_availability`. Реальные книги его не содержат: начальный/конечный
месячный остаток, отсутствие продаж, пустая ячейка и одиночный дневной снимок
не доказывают полнодневное отсутствие. Для них результат `exact_unavailable`,
а количество упущенного спроса — `null`, не ноль. Семь неизвестных дней
синтетического сценария `unknown_blank` также не объявляются stockout.

Для сценарного анализа можно вручную передать непересекающиеся интервалы
наличия и отсутствия. Каждый интервал задаёт `start`, `end`, `state`
(`available`, `out_of_stock` или `unknown`), `observed_hours_per_day`,
`scope="all_selected_warehouses"`, `author` и `reason`. Это явное допущение,
а не подтверждение исходными файлами. Интервал менее 24 часов остаётся
неизвестным. Охват отдельного склада пока не поддержан: подготовка этапа 6
использует весь выбранный транзакционный источник по SKU.

## Правило оценки

Для каждого подтверждённого дня отсутствия берутся только **более ранние** дни
с полным подтверждением наличия и известными регулярными продажами. Сначала
ищутся дни того же календарного месяца за текущий и два предыдущих года:
не менее семи дней из двух календарных недель. Если их нет, допускается
fallback из последних 56 дней: не менее 14 дней из трёх недель. При наличии
трёх и более дней того же дня недели используется их медиана; иначе медиана
всей выбранной группы. Один случайный день не даёт оценку. Число оцениваемых
дней отсутствия в месяце ограничено удвоенным числом сопоставимых дней;
дальше результат `extrapolation_limit`. Пороги — техническое консервативное
правило версии `lost-demand-1`, требующее калибровки на пилоте.

Если за день нет установленной продажи, она остаётся неизвестной. Наблюдаемая
положительная продажа в день заявленного полнодневного отсутствия — конфликт
`needs_review`, а не повод молча изменить доказательство. При недостаточной
истории нового товара или отсутствии сопоставимых дней выдаётся
`insufficient_history`, без деления на ноль и уверенной надбавки.

Результат по месяцу содержит наблюдаемый регулярный спрос из этапа 6,
оценённую добавку, скорректированное количество **для обучения прогноза**,
метод, дни-основания и причины отказа. Неизвестный или спорный месяц не
получает скорректированного значения. `adjusted_history` передаёт будущему
этапу 8 только завершённые месяцы и явно задаёт
`historical_lost_demand_as_current_backlog=0`; сами заказы пока не считаются.

Историческая проверка требует отдельной версии очистки с `as_of`, равной
проверяемой дате. Чтение строк и наличия ограничено этой датой, а опорные дни
для каждой оценки строго предшествуют оцениваемому дню. Будущий эталон из
`validation/` доступен только тестам и не читается расчётным сервисом.

## Запуск

Сначала получите версию подготовки этапа 6. Для уже созданной реальной
версии IEK №1:

```powershell
uv run --locked python -m hackalem lost-demand --cleaning-run 1 --sku 130200305_
uv run --locked python -m hackalem lost-demand-runs --cleaning-run 1
uv run --locked python -m hackalem lost-demand-report --run 1
```

Фактические ID берите из вывода команд. Синтетическая проверка требует
отдельной базы и версии очистки с датой среза `2026-01-01`:

```powershell
$env:HACKALEM_DATA_DIR = '.local/synthetic/synthetic-1-seed-20260923/model'
uv run --locked python -m hackalem clean --snapshot 2 --as-of 2026-01-01
uv run --locked python -m hackalem lost-demand --cleaning-run <ID> --sku SYN-A-009
```

Для сценария передайте `--scenario-evidence ПУТЬ.json`. Пример содержимого:

```json
[
  {
    "start": "2025-08-01", "end": "2025-08-10", "state": "available",
    "observed_hours_per_day": 24, "scope": "all_selected_warehouses",
    "author": "Аналитик", "reason": "Сценарное допущение: полное наличие"
  },
  {
    "start": "2025-08-11", "end": "2025-08-24", "state": "out_of_stock",
    "observed_hours_per_day": 24, "scope": "all_selected_warehouses",
    "author": "Аналитик", "reason": "Сценарное допущение: отсутствие"
  }
]
```

В интерфейсе те же действия доступны после выбора снимка в блоке «Упущенный
спрос при отсутствии товара». Блок не запускает оценку при открытии страницы.
