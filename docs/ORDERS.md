# Проекты заказов, утверждение и экспорт

Этап 11 создаёт проект заказа только из сохранённого расчёта пополнения одного
поставщика. Рекомендованное количество остаётся неизменным источником, а выбор
менеджера хранится отдельно по стабильному `sku`/`line_id`. Каждое изменение
количества требует автора и причины и попадает в журнал событий.

## Состояния и версии

- `draft` — «Черновик»: количества можно менять.
- `review` — «На проверке»: версия ожидает решения ответственного. Изменение
  количества возвращает её в черновик.
- `approved` — «Утверждён»: сохраняется неизменяемый JSON-снимок dataset,
  исходного `replenishment_run_id`, рекомендаций, единиц, исправлений, времени,
  основания и указанного ответственного.

Правка утверждённой версии создаёт дочерний черновик с новым номером. Старый
снимок и его экспорт не меняются. Поле ответственного — локальная запись для
аудита MVP, а не аутентификация или электронная подпись.

Положительная строка реального заказа допускается к утверждению, только если
есть артикул, код 1С, наименование, закупочная единица и полностью рассчитанный
несценарный результат с согласованными единицами. Нулевые строки в экспорт не
входят. Синтетическую версию можно утвердить для проверки процесса, но файл
всегда получает маркировку `SYNTHETIC_SCENARIO` и не является реальным заказом.

## Экспорт

CSV формируется с разделителем `;` и BOM UTF-8. Опасные для табличных программ
начала текстовых значений и коды с ведущим нулём экранируются апострофом. В
Excel текстовые ячейки получают строковый тип и формат `@`. Оба формата после
создания повторно читаются; строки, количества, единицы и остальные поля
сверяются до выдачи файла.

Лист XLSX `Метаданные` также содержит только литеральный текст, включая
ответственного и основание. Большие JSON-снимки разбиты на части, чтобы не
потерять данные из-за лимита Excel 32 767 символов в ячейке. Для восстановления
соедините значения одного `Параметр` по возрастанию `Часть` без разделителя.
Экспорт проверяет полные восстановленные метаданные и отсутствие формул.
При конкурентной правке во время утверждения операция отклоняется: сначала
нужно заново прочитать и проверить изменённую версию.

Колонки: маркировка, поставщик, артикул, код 1С, наименование, выбранное
количество, единица закупки, MOQ, кратность, ожидаемая дата либо пустота,
причина, проект, версия и статус. Возможные маркировки:

- `APPROVED_REAL` — утверждённая несценарная версия реального dataset;
- `DRAFT` — черновик или версия на проверке;
- `SCENARIO` — сценарный результат на реальных данных;
- `SYNTHETIC_SCENARIO` — синтетический проверочный набор.

Формат подготовлен для последующей настройки колонок под согласованный шаблон
1С. До получения и приёмки такого шаблона готовая интеграция с 1С не заявляется.
Отправки файла поставщику в приложении нет.

## CLI

```powershell
uv run --locked python -m hackalem order-create --replenishment-run 1 --actor "Менеджер"
uv run --locked python -m hackalem order-update --version 1 --sku ВАШ-SKU --quantity 120 --actor "Менеджер" --reason "Проверено"
uv run --locked python -m hackalem order-submit --version 1 --actor "Менеджер" --reason "Передано старшему"
uv run --locked python -m hackalem order-approve --version 1 --responsible "Ответственный" --note "Количество и единицы проверены"
uv run --locked python -m hackalem order-report --version 1
uv run --locked python -m hackalem order-export --version 1 --output .\order.xlsx
```

Те же действия доступны во вкладке «Заказы». Для черновых, сценарных и
синтетических выгрузок интерфейс требует отдельного подтверждения маркировки.
