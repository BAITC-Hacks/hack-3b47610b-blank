# Демонстрация на 6 минут

Показываем работу локального MVP на вымышленных товарах. Все количества,
клиенты и условия этого набора синтетические; это не заказ поставщику и не
доказательство экономии на реальном бизнесе. Источники и расчёты связаны
версиями, исходные PDF/XLSX не изменяются.

## Подготовка до выступления

В PowerShell из корня проекта:

```powershell
uv sync --locked
uv run --locked python -m hackalem demo --output-root .local/demo
$demo = Get-Content -Raw -Encoding UTF8 '.local/demo/demo-v1-20260923/demo-manifest.json' | ConvertFrom-Json
$env:HACKALEM_DATA_DIR = Split-Path -Parent $demo.database_path
$demo.snapshots | Format-Table
$demo.replenishment_run_ids
$demo.orders
uv run --locked python -m streamlit run app.py
```

Откройте http://127.0.0.1:8501. Dataset должен быть синтетическим, дата —
01.01.2026. `demo` уже подготовил обе версии данных, прогнозы, расчёты, проекты
и проверенные выгрузки. Номера берите из своего манифеста; не подставляйте
номера из рабочей БД. Повторный запуск не создаёт дубликаты. Для совершенно
нового показа задайте другую выходную папку.

## Сценарий

| Время | Действие на экране | Что объяснить |
|---|---|---|
| 0:00–0:45 | Выбрать снимок Systeme Electric, открыть «Данные и проверки». Показать синтетическую маркировку, происхождение и статусы. | Пустое значение не равно нулю. В реальном наборе не хватает текущего остатка IEK и ряда условий; программа их не придумывает. Реальный импорт читается кнопкой в отдельной рабочей БД, здесь загружен воспроизводимый проверочный набор. |
| 0:45–1:45 | «Рекомендации»: выбрать сохранённый расчёт Systeme из манифеста. В «Карточке товара» выбрать этот расчёт и `SYN-A-001`, затем `SYN-A-002` и `SYN-A-003`. | Обычный заказ, компоненты формулы, сезонная форма и устойчивый рост. Для нового расчёта выбрать совместимые качество/подготовку/прогнозы и «Рассчитать рекомендации». |
| 1:45–2:35 | Карточка `SYN-A-006`: фактический и очищенный спрос, «Аномалии и решения». | Одиночная сделка 500 исключена из регулярной части. Приёмка сравнивает две истории — с ней и без неё: регулярный заказ одинаков. Повторные крупные покупки и рост сохранены отдельными проверками. |
| 2:35–3:30 | Карточка `SYN-A-009`: раскрыть наличие и упущенный спрос. Показать отчёты `stockout-raw-forecast.json` и `forecast-SYN-A-009.json` в папке `reports`. | Подтверждённое отсутствие изменяет обучающую историю. На историческом августе прогноз 119 → 217, известный спрос 217. Историческая потеря не добавляется к текущему долгу. |
| 3:30–4:30 | Выбрать снимок IEK. Карточка `SYN-B-003`: сравнить расчёты `IEK` и `delay`. Показать автора, задержку14 и основание в `reports/incoming-delay.json`. Для нового сценария в форме выбрать базовый IEK, явно ввести задержку14, автора и основание. | Приход больше не покрывает ранний дефицит: появляется срочная проблема до ETA обычного заказа. Это отдельный сохранённый сценарий, базовый расчёт доступен. Точность дня ограничена равномерным распределением месячного спроса. |
| 4:30–6:00 | «Заказы»: выбрать подготовленный черновик своего поставщика, показать количество менеджера и причину. «Передать на проверку» → заполнить ответственного и основание → подтвердить локальный характер имени → «Утвердить неизменяемую версию». Отметить «Выгрузить с этой маркировкой», скачать CSV/XLSX. | Заказы разделены по поставщикам; каждая строка связана с объяснением. Старая утверждённая версия сохраняется, дальнейшая правка создаёт новую. Все файлы здесь `SYNTHETIC_SCENARIO`; отправки поставщику нет. |

Смена даты, набора или входной версии сбрасывает активные ссылки на старый
расчёт. В каждом разделе сохранённый результат нужно выбрать явно. Это не
удаляет прошлые результаты. Не пытайтесь утвердить реальный сценарий.

## Проверка и запасной показ без UI

После остановки сервера переменная `HACKALEM_DATA_DIR` остаётся указывать на demo:

```powershell
uv run --locked python -m hackalem replenishment-report --run $demo.replenishment_run_ids.'Systeme Electric' --sku SYN-A-001
uv run --locked python -m hackalem forecast-report --run $demo.forecast_run_ids.stockout_raw
uv run --locked python -m hackalem forecast-report --run $demo.forecast_run_ids.'SYN-A-009'
uv run --locked python -m hackalem replenishment-report --run $demo.replenishment_run_ids.delay --sku SYN-B-003
uv run --locked python -m hackalem order-report --version $demo.orders.IEK.approved_version_id
```

В `reports` есть JSON всех показанных расчётов и проектов, в `exports` —
8 проверенных CSV/XLSX (два поставщика × утверждённая/черновая версия × формат).
Снимки JSON на диске отражают момент подготовки; последующие UI-правки доступны
через `order-report` по новому номеру версии. Для независимой проверки истории:

```powershell
uv run --locked python -m scripts.benchmark_demo --output-dir .local/demo-validation
```

Папка должна быть новой. `acceptance-history.json` содержит результаты
проверки скрытого синтетического эталона, `benchmark.json` — время выполнения.
Методология, реальные ограничения и результаты: [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md).
Для возврата к рабочей базе: `$env:HACKALEM_DATA_DIR = '.local'`.
